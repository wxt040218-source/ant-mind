更新：2026-11-10。本次只更改导航规则并增加DSL能力，不更改消息／存档形状：wire15、content13、save4保持。v0.16木材、建筑、经济和个体成长规则继续适用。

## 对玩家的变化

蚂蚁沿目标方向同时推进两个坐标，可以按任意角度移动，不再先走完X再走Y。物理位置仍以每格1000整数单位记录，不吸附整格或限定八方向。斜行遵守同一实际速度上限，负载减速和个体等级加成照常结算；最后一步抵达准确目标，不穿越、不反复越过终点。

选择蚂蚁时，地图显示从其真实位置指向目标的辅助线及目标十字。绘图可使用浮点，模拟坐标与导航运算使用整数。当前没有障碍物寻路，建筑也不阻挡移动。

## 给蚂蚁的接口

```text
set_target(72000, 68000);
```

这条语句设置绝对目的地；引擎持续前进，不需要程序拆成逐步X／Y移动，也不需要每Tick重复下发。旧 `move_to(x,y)` 是兼容别名，旧保存程序无需重写。两者预算相同，超地图坐标夹到边界。位置未到达时世界会继续更新，程序仍能在后续决策更换目标或选择别的动作。

| 变量 | 结果 |
|---|---|
| has_target | 当前有目标时1，否则0 |
| target_x / target_y | 当前目标坐标；无目标0 |
| target_distance | 到目标的欧氏距离向上取整，单位1/1000格；无目标int.MaxValue |
| target_reached | 当前位置与目标精确相等时1；无目标0 |

这些查询只访问自身位置与当前意图，不读取隐藏地图。读取每项仍消耗正常指令预算。同一轮 `set_target` 后目标查询可以读到刚设置的意图；位置要等引擎结算才移动。

例如，只在初次决策设置一次目标：

```text
if (!has_target) {
    set_target(72000, 68000);
}
```

这份程序后续不重复发出移动动作，也不会打断既有移动。到达后目标保留作查询，移动意图变Wait，状态Succeeded／arrived。可以用 `if (!has_target || target_reached)` 再选择下一个目的地。`wait()` 明确清除目标并停止；其他物理动作照原规则替换当前意图，不会同时移动与拾取。通信动作独立，可在移动过程中收发蚁后信息。

全部默认职业、示例小组程序及生产演示脚本都改为 `set_target`；每蚁种仍全群共享一份代码。到达食物、工地或蚁巢不自动拾取、施工或交付，仍需调用对应动作。现有交互／感知距离及通信范围保持原规则；`target_distance` 是导航距离，不应替代现有方形交互距离判定。

## 实现与扩展

- Contracts/PointMath：整数平方根向上取整，以方向向量分配本Tick位移。UInt128中间平方避免坐标极端值溢出，无系统时间、随机数或浮点平方根。
- Core/MovementRule保留身体／负载／等级实际速度，只把移动几何替换为PointMath.Towards；写回夹紧后的目标，避免到达状态与目标查询矛盾。
- Core/CombatMath.Move复用同一几何，敌人和局部跟随也能沿目标方向移动；攻击、采运、通信范围没有顺带改变。
- Programs解析器提供set_target及目标查询；Runtime和MCP复用现有程序提交、热替换及观测通路。get_actions包含导航语义，未增加直接操纵个体位置的作弊接口。
- WorldCanvas仅显示目标辅助线，世界写入仍只能通过Runtime actor。

最小坐标单位导致每Tick投影有整数舍入，速度不会超过上限；极小速度和极斜方向可能只有一个坐标发生可表示的变化，但持续靠近且不会停滞。旧档可继续加载，后续路程使用新导航规则，因此不会复现旧版X优先的折线路径；同版本、同档、同指令仍确定性一致。
