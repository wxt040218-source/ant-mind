# 开发路线

当前只完成立项文档。以下是建议的推进顺序，未承诺工期或人员分工。

## M0 · 分享想法（当前阶段）

- [x] 项目介绍、玩法设计和技术架构草案。
- [x] 区分已确定方向与待讨论方案。
- [ ] 创建公开 GitHub 仓库并核验上传结果。
- [ ] 与朋友讨论兴趣、分工和最小原型范围。

验收：朋友只读 README 就能知道游戏是什么、现在有什么，以及能从哪里参与。

## M1 · 采集到交付的最小原型

- [ ] 固定种子的小地图，蚁巢、资源、采集蚁和搬运蚁。
- [ ] 内置策略执行探索、采集、装载、回巢和交付。
- [ ] 显示送达量、吞吐量、空载率与职业分工。
- [ ] 受控的限时单人挑战与结束结算。

验收：可从头玩完一局；食物不会凭空增加或重复计分；相同配置和操作可得到相同结果。

## M2 · 可编程职业与预算

- [ ] 明确观察／动作接口及受限指令格式。
- [ ] 同职业共享程序、个体状态独立。
- [ ] 指令预算、决策间隔、错误反馈、版本保存与回滚。
- [ ] 两个程序在相同初始条件下对比成绩。

验收：超预算的程序不能卡住模拟，也不能改写世界或得分；替换职业程序能产生可解释的行为差异。

## M3 · 双层 AI 闭环

- [ ] 自然语言方向转为战略计划。
- [ ] AI 生成职业程序，经校验和试运行后应用。
- [ ] 展示改动、理由、调用耗时与费用。
- [ ] 用多个固定种子对比内置基线与 AI 程序。

验收：完成“目标 → 战略 → 程序 → 执行 → 反馈 → 再优化”的闭环；记录真实的改进或退步，不能把改动次数当作优化成功。

## M4 · 经营与变化

- [ ] 蚁后繁殖、食物消耗、职业成长。
- [ ] 更多资源和一次环境变化。
- [ ] 打磨像素表现、教程和策略分析界面。

验收：玩家能通过不同的发展方向形成至少两种有取舍的策略。

排行榜、多人竞技和完整蚁群生态属于远期方向，在验证核心乐趣以后再定。
