# 最小游戏规格 · 已确认 v0.1

确认日期：2026-11-05。五轮共 36 项选择已完成，用户已确认整体理解和可调原型初值，明确选择“先完成规划归档”。本文为最小版 v0.1 的范围基线。尚未开始实现或配置 MCP。

## 游戏目标

Godot 4 .NET + C#，Windows x64 原生桌面。不限时经营，只有一种工蚁、一个固定蚁巢、一种资源、一种通用信息素。

闭环：资源随机出现 → 工蚁寻找、拾取、回巢、交付 → 公共资源增员工蚁或升级共同大脑 → 玩家要求 Codex 修改算法 → 观察实际效率变化。

先不包含障碍、地下层、战斗、饥饿、死亡、维护消耗、离线发展和多人模式。没有倒计时和胜负结算。

## 控制与观察

- 玩家在当前 Codex 聊天中给目标，按指令进行单轮或多轮优化；不自行设为常驻优化服务，游戏不内置聊天框。
- Codex 通过项目级 MCP 获取允许的信息、提交程序，并在最低库存和人口约束内自主增员与升级，记录支出及理由。
- 所有工蚁共享程序与等级，各有独立记忆、目标和负载；新生工蚁使用当前等级与程序，从空记忆开始。
- 玩家全图可见，工蚁仅局部感知；通过信息素协作，不自动向所有工蚁广播全部资源清单。
- Agent 观察模式随时可切换为“仅已发现”或“全图”，默认建议仅已发现；两者不改变工蚁感知。
- 仅已发现模式只提供蚁群发现记录、个体状态、程序与统计。旧资源记录带最后观察时间，可过时，不能从隐藏真值偷偷更新。
- 全图切回局部无法让 Agent 忘记曾看到的信息；严格局部测试应新开局，比较结果注明模式。
- 内置默认采运程序，不连接 Agent 也能玩；断线或任务结束后继续最后有效版本，可恢复默认。

官方 MCP 支持不等于当前游戏已连通；先验证当前 Codex 真正读取、修改正在运行的游戏。配置后可能需要重启连接／会话，以工具出现和调用结果为准。

## 行动与程序

受限文本 DSL 支持变量、条件、有限循环、感知和动作，由 C# 解释器计费执行。不能执行任意 C#、网络、文件或系统调用。

程序决定探索方向、资源目标、何时回巢、拾取、交付、释放与跟随信息素。引擎提供“朝目标移动”等动作，检查距离、数量、负载与冷却；到达不会自动拾取或交付。

移动目标持续生效，直到到达、被新动作改变或清除。重复指令不能提高物理速度。可读取自己的 ID、位置、负载、等级和蚁巢坐标；资源和信息素查询受感知范围限制。Agent 全局信息不自动变成每只工蚁的感知接口。

Agent 思考时旧版继续执行；新程序先校验语法、权限、大小和循环边界，成功后在 Tick 边界统一应用，失败则拒绝并返回错误位置。更新及回滚清空个体程序记忆与旧目标，保留位置、负载、等级、库存、信息素和已发现记录。

超预算或运行错误结束本次个体决策并记录原因，保留已生效的合法动作；没有新动作则继续此前有效动作，没有此前动作则等待。世界动作限制始终有效，不能靠大量指令绕过冷却。

## 信息素

一个共享浓度通道，含义由 Agent 决定，不预置“食物／回巢”语义。程序选择释放与跟随；感知和释放计入程序预算，释放不消耗库存。信息素仅衰减，不扩散，浓度有上限，玩家可查看覆盖图。

## 经济与等级

交付资源进入公共仓库，支出用于增员或共同大脑升级。每次操作原子检查最低储备、库存和人口约束。仅升级计算预算与决策频率，速度、感知和负载不变；满级可继续经营。

显示累计首次交付量、近 60 模拟秒吞吐量、库存、人口、等级、增员和升级支出及运行错误。已计分资源不能通过重复交付刷累计量。

## 玩家界面与存档

- 地图：蚁巢、工蚁、资源、负载、信息素覆盖图及个体选择。
- 统计：人口、库存、累计交付、近 60 秒效率、等级、支出。
- 个体：目标、负载、记忆、最近决策分支、预算及错误。
- 程序：只读文本、版本、修改理由、回滚、恢复默认。
- 控制：暂停、单步、1／2／5 倍速、存读档、新开局、种子、最低储备与人口限制、Agent 信息模式及连接状态。

单步指模拟一步，不是 DSL 单条指令。加速只改变每秒推进的步数，不改变单步规则。无直接代码编辑器或断点调试器。

存档在 Tick 边界保存世界、程序版本、个体记忆、目标、信息素、等级、库存、随机数状态、配置与事件时序；读档默认暂停，不重放消费指令。关闭游戏不推进模拟。

## 实施顺序与验收

1. **接入与导出**：最小 Godot C# 窗口能在 Windows 导出运行；当前 Codex 经 MCP 读取实时状态，并提交一个在游戏中可观察的改动。
2. **默认采运**：无需 Agent 即可探索、拾取和送回资源；资源刷新、增员、升级、信息素和预算遵循规则。
3. **改程序与调试**：Codex 提交新程序，玩家看到版本及行为变化；错误版本被拒绝、超预算有记录、回滚清空程序记忆和目标。
4. **完整交互**：Agent 两种信息模式过滤正确，存读档一致；同一配置、种子、程序与操作日志可重放相同结果；暂停单步与倍速遵循相同模拟规则。
5. **指令优化**：完成用户指定的单轮与多轮优化，按相同存档起点及模拟时长比较，并记录增员、等级等变量；如实报告提高或退步，不预先承诺 AI 必然更优。

总体验收：玩家能看见、理解并要求 Agent 改变蚁群的工作方式。规划已确认，本轮仅归档；收到用户开始开发的指令后才进入实施。
