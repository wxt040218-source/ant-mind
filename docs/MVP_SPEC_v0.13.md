# Ant Mind 最小经营版本 v0.13

更新：2026-11-08。wire / Snapshot=12，content schema=10，save format=1。本版本实现经营扩展的首个 M0～M3 闭环；详细原始方案见 EXPANSION_IMPLEMENTATION_PLAN.md。旧 v0.12 已归档，不再代表存档、物品和职业的最新行为。

## 游戏和控制

无游戏引擎，.NET 10 / C# 核心、Avalonia Windows 桌面、官方 STDIO MCP。20Hz，每格 1000 整数单位。地图 128×128，支持缩放和平移；视觉不改变距离、移动速度或发现规则。玩家观察和给方向，外部 Agent 规划、编写并更新职业 DSL。经营不限时，无离线发展。

同一种蚂蚁全群共享一份代码，个体记忆独立。任意混编小组只有命名参数、地点和任务数据，不能覆盖职业代码；获取新任务仍需蚂蚁显式请求蚁后。原有暂停／单步／1、2、5 倍速、五级大脑／网络、卵孵化、战斗／掉落、回血、认领／跟随、程序热替换／回滚保留。

## 四种职业

- 侦察蚁：空载快、载物慢，局部视野 6 格，载量 1；默认只探索上报。
- 搬运蚁：载量升级 1～10，按真实负载减速；原默认采运程序保留，Agent 可替换为生产物流程序。
- 兵蚁：生命 40，近战 6，显式攻击；死敌生成可运输的肉。
- **厨师蚁**：初始 0，只消耗通用卵孵化；生命 16、空载／满载移动 100／60、载量 2、视野 4。独立共享 DSL，工作率 2，其他职业工作率 1。默认代码读取小组 `station`、`recipe` 参数和 objective；没有任务时等待，不自动消费原料。

厨师暂用原侦察蚁像素身体加代码绘制的厨师帽，是可辨认的原型形象；未生成新的定稿美术。所有职业都可显式搬运、建设和加工。

## 物品和计分

| ID | 物品 | 可食用／回血 | 单位质量 |
|---|---|---|---|
| fruit | 水果 | 是／3 | 1 |
| meat | 肉 | 是／6 | 1 |
| fiber | 植物纤维 | 否／0 | 1 |
| fruit_concentrate | 水果浓缩 | 是／6 | 1 |
| protein_meal | 蛋白餐 | 是／12 | 1 |

每个持有者只有一份权威数量：源头、地面、蚂蚁、巢穴、箱子、施工材料、加工输入／在制／输出。FoodStore 负责多类型容器；独立对象仍在 EntityDatabase 中。ItemLedger 只遍历这些实际持有者计算守恒，不另存一套数量。

物品附带未结算来源点数的压缩段（CreditLot），已结算单位隐含为零。拆分先取有点数的段，再取已结算单位，合并不创造点数。初始巢穴库存为零点，野外新水果／肉每单位 1 点；纤维零点。加工保留输入剩余点数。**首次进入巢穴才结算 FirstAdmissionPoints**；中转、转交、出巢、丢弃、重捡和再次交付均不能重复结算。Delivered 保留旧显式 deliver 的搬运计数，收益比较使用 FirstAdmissionPoints。

Inventory 只包含可食用物品，纤维不能支付卵、升级或充当最低食物储备。发展优先使用水果，再按类型 ID 消耗其他食物。进食仍需显式 eat，40 Tick 后才扣除并回血，受击打断。

## 源头

正式配置：8 个果丛，成熟量上限 5，100 Tick 恢复 1，满额跳过、不积攒未来生长；4 个纤维源，每个储量 30，不再生。首个果丛和纤维源放在巢穴附近，其他按种子生成。地面散落食物作为补充：初始 4 点，每 300 Tick 尝试补充，单点随机 1～5。

harvest(sourceId,qty) 必须在一格内，由引擎校验实际储量、负载、类型和交互冷却，只把物品从源头移到个体。生长才是新物品生成，采集不能再次记生成量。

玩家和 Agent 都看不到未发现源头。离开视野后只保留上次观察量和时间。个体局部源头／设施报告也须显式 report_discovery，上报后才可由其他个体显式 request_queen_info 下载；不会自动全群同步。批量观察不重复发送每只蚂蚁的完整缓存，世界和存档保留缓存真值。

## 建设与物流

- PlanBuild(key=cache|workshop,pointX/Y) 只创建蓝图，不扣远程库存、不立即建成，不检查未知物体是否占位；建筑不阻挡路径。
- 中转箱：6 纤维＋100 有效工作 Tick，容量 40。
- 加工台：12 纤维＋200 工作 Tick，输入（含在制预留）20，输出 20，单工作位。
- 必须把纤维带到工地并显式 deposit，然后调用 work。每次 work 连续至多 10 Tick；独占一个工作位，程序在这段时间不决策。受击打断个体工作，设施进度保留。
- 完工时只消耗一次实际材料。取消未完工地保留材料供取回，不返还重复材料；不支持拆除已完工的空闲建筑。
- deposit / withdraw 指定持有者、物品、数量，0 表示巢穴；transfer 指定当地另一只活蚁。均须一格内，数量 1～100，允许受余量／容量限制的部分成功，返回实际量。个体一次只携带一种物品。
- 箱子不扩展通信范围，不自动广播库存。物流方式、工位、数量和路径都由 Agent 组合安排。

## 加工

| 配方代码／ID | 输入 | 输出 | 有效工时 |
|---|---|---|---|
| 1 / concentrate | 2 水果 | 1 水果浓缩 | 100 Tick |
| 2 / meal | 2 肉 | 1 蛋白餐 | 100 Tick |

process(station,recipeCode) 必须本地调用，检查已完工加工台、输入、输出容量、网络等级和占用后，原子地把原料移入在制。work 才推进加工；没有工蚁主动工作就暂停。完成一次后输出留在设施，必须另行 withdraw；没有自动下一批。取消批次只把现有在制退回输入一次。配方输出减少运输质量，同时保留总回血量及未结算来源点数。

本原型所有建筑和配方网络门槛为 1，可配置；仅支持单输入、单产出单位配方。能力科技、身体模块、昼夜、迁徙等 M4／M5 尚未实现。

## 接口与观察

MCP 9 个工具：get_actions、get_catalog、observe、inspect_object、inspect_group、validate_program、command、list_saves、evaluate_save。管理与物理动作分开：Agent 建计划／修改小组和代码，蚂蚁在游戏中实际执行。

新增 DSL：harvest、deposit、withdraw、transfer、process、work；item_code("fiber") 按稳定 ID 查当前数值代码。source_*、building_*、holder_stock／holder_output 只读局部；queen_source_* 是显式下载的旧缓存。完整表见 ANT_DSL.md，命令见 AGENT_API.md。

地图以简易果丛／材料／箱子／工作台像素符号显示新对象，支持点击详情。新增厨师职业菜单与只读“生产与收益”页。统计窗口最多 1200 Tick（模拟一分钟），显示真实样本长度；包含首次入巢点、采集和产出、动作 Tick、生产交互失败，并按事件发生时的种类／组记收入。不是墙上时钟收益，也未声称当前演示为最优算法。

## 存档与公平比较

SaveGame(key=slot)、LoadGame(key=slot) 在 Runtime 一致点处理。存档在桌面输出目录 saves，快速按钮使用 quick；保存完整配置、隐藏对象、随机状态、下一 ID、经济、个体记忆／通信缓存、组、程序全部历史／待应用版本、施工和在制。临时文件写完并刷盘后同目录替换；格式 1，最大 32 MiB。不是从已过滤公开 Snapshot 保存。

加载先校验格式／状态并编译所有保存程序，成功后原子替换，暂停启动，不补离线收益；旋转 WorldId、清空旧 receipts。客户端始终传 observed WorldId 和 revision；加载后没有 WorldId 或旧世界 ID 的命令均拒绝。初次世界保留无 ID 旧客户端兼容。

evaluate_save(slot,ticks,species?,source?) 从同一文件建立两个隔离分支，用同一完整规则集、RNG 和起点比较；不推进实局，不输出隐藏位置或完整存档。1～1200 Tick，现有 IPC 单次 5 秒期限，大群体长评估可能超时。候选可替换一个蚁种程序；保存的该槽有待应用版本或版本槽已满时拒绝候选更新。结果包括首次入巢增量、库存变化、死亡和程序错误，不等同多种子平衡证明。

无完整事件回放、旧版本存档迁移、自动存档或离线发展；长期耗尽对象压缩和满人口性能仍待验收。
