# 文明制度与殖民地纪元迁移指南

版本：0.2.0
适用：wire19 / content16 / save6（S1 + S2）

## 1 · 版本三跳

| 面 | 旧值 | 新值 |
|---|---|---|
| `Protocol.Version` | 18 | 19 |
| `content/world.json schemaVersion` | 15 | 16 |
| `SavedGames.Format` | 5 | 6 |

S2 不升 wire20 / content17 / save7：巢穴状态、命令参数、单格投影均复用 S1 已冻结的三跳形状。`docs/contracts/` 下四份 S0 冻结契约保持原文件名与 `contractVersion="0.1.0"`；nest-layout 分册以 v0.1.1 勘误段登记实现偏差。`PROJECT_STATUS.md` 是上游 v0.19 长记录，本轮不动。`docs/README.md` 在本仓库不存在，因此没有索引需要同步。

## 2 · 新增持久状态

`WorldState` 增加 `creature_seed`、`nest_seed`、`nest`、`institution`、`blocked_cells`、`observed_chambers` 六个持久字段。`ActiveParameters` 是每 Tick 由 `GameSession.Advance` 在跑规则之前注入的只读快照，标记 `[JsonIgnore]`，不落盘、不读写主 `RandomState`。独立子种子由总纲 §2.1 的纯函数 `Simulation.DeriveSubseeds(ulong seed)` 派生。

`content/world.json` 新增 `institutions`、`creatures`、`nestLayout` 三段；字段名按契约用 snake_case，DTO 通过 `[JsonPropertyName]` 对齐。S2 把 `nestLayout` 从 5 个网格键扩到 19 个键：7 类白名单、5 类 `wood_cost` / `work_target`、以及整数效果 basis/step/base。`ContentLoader` 的 `UnmappedMemberHandling.Disallow` 保持开启，`schemaVersion` 仍为 16。

## 3 · 制度字段与命令

五字段封闭白名单及默认值：

| 字段 | 默认 | 档位 |
|---|---|---|
| `reserve_policy` | `balanced` | `strict` / `balanced` / `loose` |
| `ration_policy` | `weakest_first` | `queen_first` / `weakest_first` / `worker_first` / `equal` |
| `labor_policy` | `balanced` | `balanced` / `haul_first` / `build_first` / `guard_first` |
| `defense_policy` | `measured` | `early` / `measured` / `late` / `never` |
| `admission_policy` | `fresh_first` | `fresh_first` / `bulk_first` / `near_first` / `type_first` |

`SetInstitution` 改一字段；`RollbackInstitution` 把历史快照恢复为一个**新版本**，不回拨 `Version`、不删历史。两者都经 Runtime actor、复用 `requestId` receipts 幂等，且只写 `WorldState.Institution`，不写 `FoodStore`、`Economy.Created`、`Generated`、`FirstAdmissionPoints` 或 `DevelopmentValue`。`History` 上限 32，超出丢最旧。失败码逐字：`unknown_institution_field`、`invalid_institution_tier`、`institution_version_not_found`、`institution_rollback_conflict`、`institution_reason_too_long`、`duplicate_request_id`。

`CommandKind` 尾部一次性追加六个成员：`SetInstitution`、`RollbackInstitution`、`PlanChamber`、`DigChamber`、`UpgradeChamber`、`CancelChamber`。S2 后四个接真路由；`GameCommand` 同时追加 `institution_field`、`institution_tier`、`target_institution_version`、`chamber_x`、`chamber_y`、`chamber_type`，S2 不再改变 wire 形状。

## 4 · 消费方式与规则数量

制度不新增 `IWorldRule`、不占 `Order`。S1 的 `GameRules.Create` 是 22 条规则；S2 只新增 1 条 `core.nest-construction`(Order 33)，故现在是 **23 条规则**。`InstitutionMechanics.Resolve(world)` 产出每 Tick 纯整数参数快照，消费点如下：

- `reserve_policy`：`EatingRule` / `ClaimCleanupRule` / `ProductionActionRule` / `TechnologyProgression.Pay` / 命令层 reserve 校验读 `EffectiveReserve`；`SetMinimumReserve` 命令仍写 `world.Config.MinimumReserve`，形成 config 基线与制度档位双轨。
- `ration_policy`：`EatingRule`、`ClaimRule` 用稳定排序键；不改 `HealAmount` / `EatingTicks=40`。
- `labor_policy`：`WorkRule` 乘工种权重；`ProductionActionRule` 让 chef 的 process 意图先处理。权重默认 100，整数乘除保持旧行为精确等价；不改 `workUnitsPerExperience=10`、不改 `SpeciesProgramCatalog`。
- `defense_policy`：`CombatRule` / `FollowRule` 威胁达阈值时 guard 组前置；`QueenCommunicationRule` 缩短通信冷却。手动 `Attack` 语义与 `EnemyDamage=2` 不变。
- `admission_policy`：`InteractionRule` 只重排 Deliver 意图的处理顺序，`Ants` 存储顺序与 `Economy.Admit` / `FirstAdmissionPoints` 判定不变；`ClaimRule` 用同键裁决。

兼容口径：没有 `ActiveParameters` 的直接 `rule.Apply` 单元测试自动回退到旧的 `world.Config.MinimumReserve` 与旧顺序，所以旧检查逐帧不变。真实 actor 世界由 `Advance` 注入快照后才启用制度参数。

## 5 · 巢穴规划（S2）

地下 `NestLayout` 是 9×9 整数网格，`CoreIndex=40` 是唯一 `core`；格索引 `(chamberX,chamberY)` 不进地表 `Point`、不乘 `Point.UnitsPerCell`、不进 `world.Objects` / `EntityDatabase` / `BuildingView`。`ChamberCatalog` 封闭 7 类房间，`Phase` 封闭 `planned/digging/active/cancelled`。

纯函数 `NestLayout.ComputeConnectedMask(Cells)` 从核心做 4 邻接 BFS（上右下左、无对角、只 `Phase=="active"` 且非 `empty` 可通行）；`NestEffects.Aggregate` 按索引升序只聚合连通 active 房间，全整数 basis=100。`Recompute(config)` 写回 `ConnectedMask` 与 `CapacityBonus`，且只在 Order33 完工/相位变化时触发。局部可见集合 `ObservedChambers` 扩进既有 `core.local-observation`(Order5)，不新增 Order6 规则。

四个命令 `PlanChamber` / `DigChamber` / `UpgradeChamber` / `CancelChamber` 经 Runtime actor 的 `ApplyNestCommand` 落状态。冻结契约要求 `plan_chamber` 目标格已 discovered；S2 勘误放宽为「已 discovered 或与任一连通格 4 邻接」，否则初始只有核心可见时无法开第一间房。`dig/upgrade` 只从 `FoodStore.Take(Wood,cost)` 预留到 `ChamberCell.WoodReserved`，`cancel` 只退 `WoodReserved`，完工才由 Order33 一次性 `Economy.Consumed`；`ItemLedger.Held` 把 `WoodReserved` 计入实物，保证 `Imbalance` 全 0。四动作绝不写 `Created` / `Admit` / `Generated` / `FirstAdmissionPoints` / `DevelopmentValue`。

`core.nest-construction`(Order33) 复用 `WorkRule` 的 builder 工作率、 veterancy、固定点余数、受击中断和 `WorkTicksRemaining` 语义；地下 worker slot 是 `HashSet<int>` 按 chamberIndex 局部集合，不碰地表 `BuildingPlacement` / `NextBuildingId`。

## 6 · DSL 与局部投影

`AntDsl.cs` 常量 `MaxSourceLength=8192`、`MaxNodes=512`、`MaxNesting=8`、`MaxRepeat=16`、`MemorySlots=16` 全部不变，`GroupValue` 不新增成员，默认程序仍在 level1 64 预算内。

S1 已加：`set_institution("field","tier")`、`institution("field")`、`institution_version`。S2 新增四个动作 `plan_chamber(x,y,"type")`（3 参）、`dig_chamber(x,y)`、`upgrade_chamber(x,y)`、`cancel_chamber(x,y)`（2 参）；`plan_chamber` 的字符串类型编译期转整数码，非法报 `Invalid chamber type '{name}'.`。新增只读量 `nest_capacity` 与 `chamber_count("type")` / `chamber_connected(x,y)` / `chamber_level(x,y)` / `chamber_phase(x,y)`。未 discovered 的格 `chamber_connected` / `chamber_level` / `chamber_phase` 返 0，`chamber_phase` 的 `empty` 对应 `PhaseCode("empty")=0`；`chamber_count` 只计已 discovered 且连通的格。

DSL 的巢穴意图写入 `Decision.ChamberX/Y/TypeCode/Action` 并拷进 `AntView`，不直接写 world；唯一全局写入口仍是 Runtime actor 命令。`Perception` 只拿聚合 `NestCapacity` 与 `ObservedChamberViews`，永不暴露 `Cells` 全量。

## 7 · MCP

S1 新增第 16 个只读工具 `inspect_institution`；S2 新增第 17 个只读工具 `inspect_chamber(chamberX,chamberY)`，返回单格 `{chamberType,level,phase,connected,discovered,constructionWork,workTarget}`，未 discovered / 越界返 `ChamberView.Hidden` 的 empty 形状。`inspect_chamber` 复用 `observe`，不改 `WireRequest` / `Gateway` 分派。`Snapshot` 只新增 `nest_capacity` 与 `observed_chambers`，不返回 `Cells`；player 与 Agent 同投影。

`get_actions` 的 `protocolVersion` 为 19，S2 后暴露四个 Chamber kind 并给出说明串；`command` 追加 `chamberX` / `chamberY` / `chamberType` 三个可选参数。两处工具数断言已同步：`AgentMcpCheck.cs` 的 `names.Count==17`、`McpCheck.cs` 的 `GetArrayLength() != 17`，并补 `inspect_chamber` 真实 `tools/call` 冒烟。

## 8 · 旧档迁移

`SaveMigration.Upgrade` 的链为 `4/15..17 → 5/18 → 6/19`。注意 4→5/18 一级显式写死 5/18，不能引用已升到 6/19 的常量，否则会跳过 5→6 级。`UpgradeV5` 六步：

1. 由旧档 `World.RandomState` 确定性派生 `CreatureSeed` / `NestSeed`，不读写主随机源。
2. 补 9×9 `NestLayout`：仅中心 `(4,4)` / index 40 为 `core`、`active`、`discovered=true`，其余 80 格 `empty` / `planned`。
3. 补 `InstitutionState` Version=1、五默认档位、`Reason=migrated-from-save5`、`AppliedTick=save.World.Tick`、History 含初始版本。
4. 补 `BlockedCells=[]`、`ObservedChambers=[40]`。
5. `EnemyView` 七个标量补默认：`creature_kind="predator_beetle"`、`carcass_food_type="meat"`、`block_cells=0`、`herd_id=0`、`last_graze_tick=-1000000`、`target_chamber_x=-1`、`target_chamber_y=-1`。
6. `ObservedBuildings`、旧工地 `ConstructionItem=fiber`、`cache.CanFeedAnts` 保持不动；`NormalizeLegacyJson` 不新增分支。

迁移只在内存候选上执行，不回写旧档。`SavedGames.Validate` 增补制度、巢穴、子种子、BlockedCells、ObservedChambers 与 EnemyView 字段级校验，并校验 `ObservedChambers` 升序去重、逐位等于 `Nest.Cells[*].Discovered`。

## 9 · 检查与验证

`tools/AntMind.Checks/InstitutionCheck.cs` 与 `tools/AntMind.Checks/NestCheck.cs` 注册进 `Program.cs` 的单一 `Check(bool,label)` 计数器；S1.5 的两条负向早拒断言在 S2 全部反转。`All {checks} architectural checks passed.` 仍只有一行，真实 N 以本轮实跑日志为准。

四条不变式由 NestCheck 坐实：① 同 seed / 同命令序列两遍逐 Tick 摘要一致；② plan/dig/cancel/complete 每步 `ItemLedger.Imbalance` 全 0、`CreatedItems` 不变、`ConsumedItems[wood]` 只在完工增加；③ 反复造→取消不抬 `FirstAdmissionPoints` / `DevelopmentValue`，重复 `requestId` 不二次扣料；④ player 与 Agent 可见集合相等，未 discovered 格 `inspect_chamber` 返 empty，DSL 只读量返 0，`Snapshot` 不含 Cells。

全链构建、`AntMind.Checks` 实跑、Python unittest、模型能力评测桥、同种子逐帧一致、旧档字节不变、commit / push / `ls-remote` 回读结果以本轮交付回报为准。

## 10 · S3 边界

S2 只实现巢穴规划。`core.creature-ecology`(Order1)、天气、多蚁群 / 第二 AI 巢、地图展示真实行为仍冻结。`NestSeed` / `CreatureSeed` 只存档派生，S2 不读来驱动生态或施工随机。`NestLayout` 的 C# 属性用 `Width` / `Height`，JSON 名仍为 `grid_width` / `grid_height`，与冻结契约的序列化形状一致。
