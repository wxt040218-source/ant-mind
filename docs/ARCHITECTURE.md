# 无游戏引擎技术架构

2026-11-07 修订。项目采用无引擎 C# 核心、Avalonia 桌面与独立 MCP 接入。v0.3 双蚁种和按种类 DSL 已接入；手动存档及当前 Codex 会话连接验收仍待开发／核验。完整范围见 [最小游戏规格](MVP_SPEC.md)，实际边界见 [框架说明](FRAMEWORK.md)。

## 数据与控制链路

```text
玩家 → Codex / 其他 MCP 客户端
                ↓ STDIO
          AntMind.Mcp
                ↓ 命名管道
          AntMind.Runtime ← 本地 UI 操作
                ↓ Tick 边界命令队列
    AntMind.Core + AntMind.Programs
                ↓ 不可变快照 / 事件
    Avalonia 桌面界面 / 存档 / 无界面评估器
```

Contracts 定义双方共享的数据契约。Core、Programs 和 Contracts 不引用 Avalonia、MCP SDK 或桌面 API。Runtime 组合核心与解释器，拥有唯一的世界写入入口；Desktop 和 Mcp 是适配层。Evaluator 复用同一 Runtime，不为评估重新实现规则。

## 调度与状态一致性

- 模拟采用独立串行执行上下文，固定 20 Tick／模拟秒；UI 通过只读快照展示与插值。
- 基础移动、距离、负载、资源与动作冷却由 Core 结算；DSL 决定目标及何时发出动作。
- UI 和 MCP 的修改请求统一进入 Runtime 命令队列；在 Tick 边界校验、结算并记录结果。
- 暂停时管理命令也能通过串行命令处理生效，但不推进模拟；单步只推进一个 Tick。
- 请求包含 requestId 和预期程序／世界版本。Runtime 对重复消费请求返回已有结果，对过时写入返回冲突，避免断线重试重复消费资源。
- 命名管道采用有界消息、协议版本和请求响应关联；连接断开不停止模拟。仅允许当前本机用户连接，MCP 日志写 stderr，stdout 专供协议使用。
- 倍速改变推进节奏，不改变步长、预算计费或世界规则。

## 可扩展边界

| 扩展目标 | 入口与约束 |
| --- | --- |
| 调整地图、资源、升级成本 | content 中带版本的 JSON 配置；启动时校验并写入存档 |
| 新资源或新规则 | 稳定内容 ID + C# 规则接口；按固定顺序注册，在模拟线程执行 |
| 新程序指令 | 指令注册表同时声明语法、权限、预算和执行语义；不得绕过局部感知 |
| 新 Agent | 实现同一 MCP 工具契约；无须改动 Core 或 Desktop |
| 新界面或批量实验 | 读取同一快照、提交同一命令；可替换桌面宿主 |
| 新素材与显示层 | 资源清单及地图绘制适配；不改变世界真值 |

M1 先固定查询、命令、快照和版本契约。后续增加规则接口时提供一个普通项目引用示例和兼容说明；不提前制造空接口或要求扩展者实现整套框架。第三方 C# 扩展属于可信开发代码，与沙箱内执行的工蚁 DSL 区别明确。

## Agent 信息权限

玩家 UI 和 MCP 统一只能看已发现食物，不能直接序列化完整世界；Visibility 全图切换已停用。蚁后数据仅来源于实际上传。已发现资源记录保留最后观察时间，不从未知真值偷偷更新。个体 DSL 始终使用该只蚂蚁的局部感知接口。

MCP 提供种类状态、程序历史、程序校验／应用、回滚、指定蚁种增员、升级和操作结果查询。修改携带理由并服从最低储备与人口约束。限次／多轮优化由用户指令控制，游戏不内置模型服务调用。

## DSL、存档与回放

DSL 只开放有界感知、标量、条件、有限循环、独立记忆和动作。新版本先校验，失败则旧版继续；运行超预算结束本次个体决策并保留已生效的合法动作。更新与回滚清空个体程序记忆和目标，保留世界。

种子随机数、稳定遍历、整数／定点坐标与固定结算顺序保证可重放。存档含 schemaVersion、配置、程序、记忆、蚁后汇总与待上传发现、随机状态、Tick 和操作序列；不支持的存档版本明确拒绝或经显式迁移加载。回放使用已提交的程序与命令，不重新请求模型生成。
