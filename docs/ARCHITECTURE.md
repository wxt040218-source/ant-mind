# 最小版技术架构

2026-11-05 规划已确认，尚未实现。范围以 [最小游戏规格](MVP_SPEC.md) 为准。

## 控制链路

```text
玩家在 Codex 聊天中提出目标与单轮／多轮要求
    ↓
Codex：观察、修改工蚁算法、安排增员和升级
    ↓ 项目级 MCP
本地桥接进程：受限观察／程序／发展工具
    ↓ 本地通信（具体实现待接入验证）
Godot 桌面游戏
    ├─ 独立 C# 模拟核心：资源、移动、交互、信息素、人口与等级
    ├─ 受限文本 DSL：解析、校验、预算、记忆、动作
    ├─ 界面：地图、统计、只读代码、个体决策和控制
    └─ 存档／操作日志：状态、配置、随机数与生效 Tick
```

首版由外部 Codex 承担 Agent 工作，游戏不内置模型调用、聊天框或模型密钥。任务节奏服从用户指令，断开后工蚁继续最后有效程序。

## 核心边界

- 模拟核心不依赖 Godot 场景和物理帧率，固定 20 Tick／模拟秒；渲染独立。
- 基础移动由引擎执行，目标、拾取、交付和信息素策略由程序决定。
- DSL 只开放有限感知、变量、条件、有限循环、记忆及动作；不能直接改世界、库存、分数或调用系统。
- 集合遍历、格子采样等实际工作量必须计预算，不能用高级查询绕过等级限制。
- MCP 观察按全图／已发现模式过滤；工蚁感知始终局部。玩家的完整地图展示不改变工具权限。
- MCP 增员／升级原子检查资源储备、人口和费用，记录理由；程序更新在 Tick 边界应用。

## 程序版本和错误

新程序校验失败则拒绝应用，旧版继续。个体运行错误或超预算结束本次决策，保留合法动作并记录原因，世界继续更新。

更新与回滚清空个体程序记忆及旧目标，保留世界。默认程序可独立运行。保留版本、代码和变更理由，方便观察与恢复。

## 存档与确定性

种子随机数、稳定遍历与动作结算顺序，优先用整数／定点表示世界规则。保存配置、完整状态、程序、记忆、信息素、随机数状态及操作生效 Tick。

模型输出未必可重复，因此回放使用实际提交的程序与操作。倍速只改变 Tick 推进速度；同初始状态、配置与输入应得到一致结果。

## 首个技术验收

先导出最小 Godot C# Windows 程序，并通过当前 Codex 实际读写运行中游戏。MCP 的官方支持路径不代表当前会话已得到工具；不得把配置文件存在当作连接验证成功。
