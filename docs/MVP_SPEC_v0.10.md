# Ant Mind 最小游戏规格 v0.10

2026-11-08：基于 v0.9 加入分类食物、小组、显式进食和协作；历史规格见 MVP_SPEC_v0.9.md，实施范围见 V0.10_PLAN.md。

## 设计方向

规则支持不同算法和玩法组合，不追求所有流派收益接近；优先修复能反复计分、绕过动作或资源约束的无脑刷分方式。数值为可配置原型初值，尚无平衡结论。

## 世界与生命周期

无引擎 C#/.NET 10、Avalonia、官方 MCP SDK；固定 20Hz、1000 单位/格、确定性随机及 Runtime actor 唯一写入。平面地图、固定蚁后、自然水果与敌人掉落的肉两类食物（每处生成时随机容量 1～5，初始数量等于容量），不限时、无饥饿与维护消耗。

初始侦察蚁／搬运蚁各 5 只。侦察蚁空载／载物速度 200／20、载量 1、视野 6；搬运蚁空载速度 120、基础载量 1、视野 3。速度单位为每 Tick 固定点单位（20Hz、1000 单位/格）。搬运蚁速度 = 120 − 6 × 实际携带数量，携带 1～10 份时为 114～60；侦察蚁载物后明显慢于满载搬运蚁。升级只解锁容量，同样负载速度不变。

蚁后菜单以默认 20 资源生产一枚通用卵，蚁种菜单用一枚卵孵化为所选种类，无第二次资源扣费。人口上限在孵化时检查，最低储备在生产时检查，失败不扣卵。初始卵为 0。

## 升级

全群共享五级大脑，提升指令预算和决策频率。额外增加搬运蚁身体载量等级，同类现有成员和以后孵化的成员共享。

默认搬运容量逐级为 1～10；对应九次升级费用为 80、120、180、260、360、480、620、800、1000。侦察蚁不受此升级影响。真实拾取、移动减速、程序 capacity 和菜单显示都使用有效容量。

UpgradeCarry 必须指定 species=hauler 并给出 reason；检查库存、最低储备及最大等级。花费独立记入 CarryUpgradeSpent。

## 蚁群网络与科技

蚁群网络是全群共享的科技等级，独立于大脑和身体载量。默认五级，范围及升级费用由内容配置决定：

| 等级 | 蚁后通信半径 | 升至本级费用 |
|---|---|---|
| 1 | 16 格 | 初始 |
| 2 | 24 格 | 60 食物 |
| 3 | 32 格 | 160 食物 |
| 4 | 48 格 | 400 食物 |
| 5 | 64 格 | 1000 食物 |

UpgradeNetwork 要求 reason，通过 Runtime 原子检查库存、最低储备和等级上限；同请求重试不重复扣费，费用单独记入 NetworkUpgradeSpent。升级后地图范围、通信判定及快照立即采用新等级；下载信息仍需程序显式请求，升级不会自动同步缓存。

content/world.json 的 technologies 声明每项能力的 id、name 和 requiredNetworkLevel。核心规则用 WorldState.IsTechnologyUnlocked(id) 检查权限，未知 id 默认关闭。当前只注册已实现的 queen.communication（Lv.1）。后续加入高科技能力时，必须同时登记等级要求，并在相应规则／命令执行入口调用该检查；配置本身不自动创造玩法效果。

旧 SetQueenRange 始终拒绝，不能绕过付费等级直接扩大范围。配置使用 NetworkRanges、NetworkUpgradeCosts，不再接受旧 queenRangeCells 字段；尚无存档迁移需求。

## 蚂蚁程序与动作

默认按蚁种共享 DSL，小组可按蚁种独立覆盖；个体独立记忆与观察。移动、拾取、原地放下、交付、请求蚁后信息和上报发现均由代码显式调用，详见 ANT_DSL.md。

移动是持续目标，其他物理交互只尝试一次；拾取不会自动走向食物，交付不会自动回巢。提供成功／失败／进行中状态。drop 把携带食物放回地面，不产生食物、不计分；只有最终交付计入得分，不能通过拿起／放下循环刷分。

## 信息

蚁后圆形通信半径由蚁群网络等级决定，默认 Lv.1 为 16 格，不能直接设置。局部观察只存本只蚂蚁待上传记录，不自动上传。程序调用 report_discovery 才上传，request_queen_info 才下载；通信默认冷却 10 Tick。同次上传和下载可一起执行。

范围外请求失败，保留已有缓存，不提供新的汇总信息。新下载缓存在下一次决策可见；queen_info_tick 显示缓存时间。蚁后只知道已上报观察，旧记录可能过期。玩家与 Agent 都只能读取已发现食物，已取消全图模式。

规则顺序以文末 v0.10 顺序为准。

## 独立对象数据

WorldState.Objects 是本局唯一对象库（内存数据库），按 kind:id 索引，食物、蚂蚁、蚁后各自有独立记录；不是每个对象一个数据库文件。目前未实现磁盘持久化和完整存档。

食物记录包含 MaxCapacity、Amount、IsDiscovered、CreatedTick、DiscoveredTick、LastObservedAmount、LastObservedTick 和 Properties 扩展字段。自然食物的容量在生成时随机确定为 1～5，拾取改变当前数量而不改变容量；搬空后仍在对象库保留零数量记录。大批放下食物时按容量拆成多个对象，合并不能扩大已有对象容量，不能凭空产生食物或得分。

蚂蚁记录包含独立 ID、种类、位置、携带量、目标、意图、程序版本、个体记忆、通信缓存、决策记录、出生 Tick 及扩展属性。同类共享身体／大脑升级，小组×蚁种程序可覆盖全群蚁种默认。蚁后有独立 queen:1 记录；科技、经济等蚁群级属性仍由 WorldState 管理。

玩家和 Agent 的食物投影统一来自已发现对象的最后观察数据；从未发现的食物不显示、不提供对象查询，也不泄露全局生成量（公开 Generated 为 null）。离开视野后保留上次观察值，再次观察才更新；失去视野不撤销发现标记。对象 ID 猜测对未知和不存在对象统一返回 object_not_found。旧 Visibility 命令固定拒绝 discovery_only，即使 player=true 也不能绕过过滤。

## MCP 指示灯

完成官方 SDK initialize/initialized 握手后，桥接进程向桌面宿主登记会话，每 2 秒发送心跳。宿主成功收到心跳才显示绿灯；仅启动进程或读取游戏不会变绿。正常断开移除会话，异常退出后 6 秒过期变灰；多个客户端分别计数，暂停不影响连接状态。连接状态与模拟世界分开维护，不改变 Tick、revision 或随机状态。

## 界面与接口

主菜单选择蚁后或蚁种。蚁后页面生产卵、升级蚁群网络；蚁种详情显示共享大脑升级、搬运载量升级（仅搬运蚁）、用卵孵化与独立程序查看。个体面板显示动作及通信状态。

全部玩法操作通过同一 Runtime 命令队列；MCP 工具 observe、command、get_actions、validate_program、inspect_object，包含 UpgradeCarry 和 UpgradeNetwork。见 AGENT_API.md。协议／快照版本 10，内容 schema 9；宿主和客户端同步重建。

手动存读档、事件回放、当前 Codex 会话实际 MCP 接入仍待后续完成。验证要求包含确定性、资源守恒、显式通信隔离、单次动作、重复请求和升级后实际载量。


## 阶段目标与挑战

content/world.json 的 milestones 配置每个目标的 ID、名称、说明、指标、阈值、前置目标和限时 Tick。默认包括：发现 5 处天然食物、送回 50 份、扩群至 20 只、网络 Lv.3，以及解锁后 12000 Tick（10 分钟模拟时间）内使总交付达到 200。限时从前置目标完成时开始，截止 Tick 当步可完成，过期锁定为失败；其余经营继续，挑战不重置世界。暂停不计时，倍速不改变单步规则。

每个目标完成／失败只登记一次，保存开始及完成 Tick。当前奖励是成就记录与完成时间，不注入食物或科技权限。探索只统计已发现天然食物，放下的食物不计入；不泄露未发现资源数量。完成时间记录本局模拟时间，不声称跨重启保存。

新增指标时扩展核心 MilestoneRule.Current 与验证支持项，再在内容中配置目标；新内容可组合已有指标和前置链，缺失／循环前置拒绝加载。记录在 WorldState.MilestoneProgress，规则 Order 50，在发现 45 之后；暂停时管理命令也立即更新目标。

侦察巡查和可靠搬运 DSL 现在随 Programs 程序集嵌入，是新局默认程序，不再依赖手动重新提交。源文件 content/programs/*.ant 为单一编辑来源，修改后须重新构建才更新默认版本。运行中 Agent 提交的临时新版本仍不自动跨进程保存；完整存读档尚未实现。


## 敌对生物、兵蚁与尸体食物（v0.9）

正式内容启用 combat.enabled；每 1200 Tick 从边缘确定性随机生成一只掠食甲虫，存活上限 3。配置默认生命 18、伤害 2、移动 70 单位/Tick、视野 8 格、攻击冷却 20 Tick。无附近蚂蚁时朝蚁后移动，发现附近蚂蚁时追击；进入蚁后近战范围后优先攻击蚁后。未发现敌人不暴露；发现后离开视野使用最后观察位置和生命值。内部 WorldConfig 默认关闭自动刷怪供无敌人模拟使用，正式 content/world.json 为开启。

兵蚁通过对应职业页面消耗通用卵孵化，初始为 0 只。默认生命 40、伤害 6、攻击冷却 10 Tick、空载移动 180、视野 8 格、载量 1。工蚁默认生命 12、伤害 0。所有属性可配置，兵蚁有独立 DSL 与版本槽。默认在巢穴附近守卫，发现局部敌人后追击，进入一格近战范围后显式 attack(enemy_id)。未发攻击动作不自动攻击；距离、冷却、目标存活与伤害资格由 Core 校验，重复发指令不能绕过冷却。

敌人生命归零后保留独立 enemy 记录，只生成一次尸体食物。数量在敌人出生时确定性随机为 1～5，尸体保留来源敌人 ID；食物原型 Origin=Carcass，不计入天然资源探索目标。击杀不直接加库存，现有 pickup/deliver 完成搬运后才计入交付。Generated 在尸体转化时增加相同数量，之后继续满足资源守恒。

蚂蚁生命归零后退出活动列表、停止执行程序，保留可查询死亡记录；已携带食物掉落，不生成蚂蚁身体食物。新生 ID 取对象库历史最大值 +1，不能复用死亡个体 ID。蚁后默认生命 100；被击败后 Runtime 自动暂停，拒绝继续运行／推进及发展命令，现阶段通过重新打开游戏开始新局。

战斗与其他规则的完整排序见 v0.10 章节。战斗按蚂蚁 ID 先结算显式攻击，再按敌人 ID 结算敌方攻击；已击败的敌人不反击、不重复产出。

协议 v10，内容 schema 9。Snapshot 返回 Enemies（仅已发现、最后观察状态）、DeadAnts、Defeated、EnemiesDefeated、AntsLost，Queen 包含 Health/MaxHealth。地图以红色标记敌人、绿色标记兵蚁、棕色标记尸体食物，兵蚁目前使用简单像素图标。


## 分类食物、小组与进食（v0.10，已实现）

详细设计与验收范围见 [V0.10_PLAN.md](V0.10_PLAN.md)。自然食物为 fruit 水果，尸体为 meat 肉；来源 Origin 与食物类型 FoodType 独立。每次负载只装一种，未清空前跳过异类食物。拾取、交付、放下、死亡掉落都保留类型，只合并同类型同坐标食物。FoodStore 是分类库存唯一真值，Inventory 是总量派生值；初始 100 份水果。生产／升级水果优先，其余类型按 ID 排序扣除，单位份数价值相同。Foods 注册 ID、显示名称、HealAmount，默认水果 3／肉 6。

小组最多 32 个，名称 1～40 字符、任务说明最多 256 字符；稳定 ID 不复用。每个活蚁至多一组，可任意混编。每组有集合点 Rally、目标点 Objective、撤退点 Retreat 和版本。创建、调整成员、任务点与删除均走 Runtime actor。蚁种程序可被小组×蚁种覆盖，最多各 32 版本；提交／回滚在下一 Tick 激活并清空相关个体记忆和目标。全群程序更新不覆盖小组独立程序。ClearGroupProgram 立即清除该覆盖及其历史，下次决策使用最新全群蚁种程序；解散移出全部活成员并清除覆盖。删除小组后历史死亡个体保留其原 GroupId。

程序部署／成员管理是直接管理操作；任务点必须通过显式 request_queen_info 下载到 ReceivedOrder，下一次决策使用。离线保留最后收到的同组任务，不获得新版本；换组时清除旧缓存。任务说明供玩家／Agent 阅读，不会由引擎自动翻译成行为。

eat(type) 吃一份同类型携带物，若没有则只允许在蚁后一格内使用库存，并遵守最低储备。进食 40 Tick，期间不移动、不执行新决策；结束时再次检查并扣一份，实际恢复不超过满血。受击中断，不扣食物；当 Tick 受击无法开始进食。满血、无同类食物、无效类型均有明确动作结果。蚁后不自动恢复，死亡不能复活。FoodEaten 是所有进食份数，HealthRestored 是实际回血；Delivered 仍是历史毛交付，不是净库存收益。完整守恒：初始库存 + Generated = 库存 + 地面 + 活蚁携带 + 生产／升级支出 + FoodEaten。

claim_food(id,quantity,ttl) 只认领局部看到的食物，按个体 ID 稳定结算，一蚁最多一项，部分剩余可分配。认领是协作建议，不锁死 pickup；拾取成功释放自己的认领，死亡／耗尽／到期清除，其余认领按剩余数量裁剪。个体可读局部认领，显式蚁后请求还会下载已上报食物的认领快照；过期缓存不从真值更新。follow(id,distance) 仅对本只蚂蚁视野中的活队友有效，计算朝最后可见位置的移动目标，未见目标则失败。不断跟随须程序重复调用；队列、阵型、攻击、撤退都由代码决定。

当前完整顺序：敌人刷新 0→观察 5→程序 10→通信 15→认领 16→跟随 19→蚁移动 20→敌移动 21→战斗 25→采运 30→进食 31→刷新 40→发现 45→认领清理 46→里程碑 50。

桌面新增“小组与任务”页：创建／保存／解散，勾选混编成员，三种任务点，按组内蚁种查看程序／回滚／沿用全群。地图用浅色框标识组员、绿色短条标识进食；顶部水果／肉分列。食物、个体详情显示类型、归属、任务缓存及进食状态。所有按钮 API 见 AGENT_API.md；完整存档仍未实现。
