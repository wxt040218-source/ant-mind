# 玩法设计草案

状态：讨论稿。双层 AI、单人挑战、简约像素风来自发起人的明确选择；下面的细化规则仍可调整。

## 一局游戏的体验

玩家给出发展目标 → AI 总指挥分析状态 → 分配职业与资源任务 → 生成或修改职业程序 → 蚁群执行 → 统计结果 → AI 提出下一轮改进。

玩家主要观察地图、下达方向、比较效果。程序详情和决策记录可以展开查看。应当能够看到 AI 修改了哪个职业、修改原因和修改后的实际成绩。

## 蚁群与资源

保留生产类、搬运类两大类。原型阶段先用采集蚁和搬运蚁：采集蚁把天然资源转为可搬运食物，搬运蚁负责取货并送回蚁巢。侦察、加工、速运、重载等职业随后逐步讨论。

蚁后消耗食物繁殖，AI 决定新生蚂蚁的职业。原型先验证固定蚂蚁数量下的运输闭环，再加入繁殖和维护消耗，以便分别验证每个系统。

资源点至少有位置、剩余数量和采集时间。后续可以增加重量、营养价值、腐烂和危险。优先比较距离、采集速度与运输能力产生的瓶颈，避免一开始加入太多变量。

## 职业大脑升级

把成长拆成可衡量的能力：

- 每次决策可执行的指令预算。
- 两次决策之间的模拟 Tick 数。
- 可读取的感知范围、可保存的记忆量。

程序长度不等于时间复杂度。拟通过受限指令解释器按操作计费，并对路径查询等高成本操作单独计费，实际预算和等级数值待原型验证。升级成本、职业间等级是否独立均待讨论。

## 评分草案

主成绩拟采用：**首次成功交付至蚁巢的食物价值总量 ÷ 挑战模拟时长（分钟）**。

食物一旦计入交付量就不能通过取出、再交付重复计分；繁殖消耗独立记账。运输总量与库存净增长都应显示，让玩家看到效率与发展投入的关系。

辅助指标：空载移动比例、采集后待运数量、各职业闲置时间、人口变化、程序预算消耗、运行错误次数。

比较两种策略时，保持地图种子、初始状态、事件序列、挑战时长和规则版本一致；程序版本与战略操作记录也需要保存。成绩使用模拟时间，AI 等待期间是否暂停挑战是待确认的规则。

## 环境与挑战

原型先做一张固定种子地图和限时采运挑战。后续逐步加入资源枯竭、刷新、降雨和道路变化，要求策略有可观察的适应过程。

事件也从同一个种子生成，方便重放和比较。多个种子的表现需要分别记录，避免只优化某一张地图。

## 首轮需要一起讨论

1. 主评分用运输总量还是扣除维护、繁殖成本后的净收益？当前草案把前者作为主成绩。
2. AI 修改程序后自动应用，还是先给玩家预览？
3. 升级更强调计算预算、决策频率，还是可调用的能力？
4. 最小原型先做纯采运，还是必须包含一次繁殖才有经营感？
